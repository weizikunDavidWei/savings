# SAVINGS. / 消费升级基金

**Save small. Dream big.**

一个无依赖、离线可用的个人虚拟储蓄工具。全部页面、样式、逻辑都在 `index.html` 中，无需安装、编译或启动服务。

## 直接使用

双击 `index.html`，在 Safari 中打开。初始余额为零，没有示例流水。默认四个快捷项目是可修改的操作模板。

- **外观**：右上角月亮 / 太阳按钮一键切换，或在「数据与设置」选择彩色日间、黑白深色、跟随系统。夜间版仅使用黑白与中性灰，图片、图表、弹窗也保持单色；设备会独立记住选择，切换不改变任何储蓄数据。在「数据与设置 → 外观」勾选「纯黑背景」，可将深色模式的页面、卡片、输入框和弹窗底色改为 `#000000`，适合 OLED 屏幕；白色强调区域、文字、分隔线与图表仍保持对比。默认关闭，独立保存于本设备，跟随系统进入深色模式时也会生效。
- **总览**：点击彩色卡片，立即记录一笔储蓄。使用提示中的「撤销」或 ⌘Z / Ctrl+Z 撤回最近操作；连续点击会分别记录。
- **管理项目**：添加、修改、删除项目；用上下箭头排列顺序。支持税前自动加税、税后最终金额、自定义颜色与类别。
- **任意金额**：点击与快捷项目同级的大卡片，滑动「元 / 分」拨轮，或直接点大数字输入；不填名称也能保存。名称、分类、备注和日期放在可展开选项中。勾选「自动加税」可按默认税率计算，初始税率为 13%，在「数据与设置 → 默认税率」修改；大数字输入税前金额，保存按钮显示含税总额。记录保留税前金额及当时税率，编辑或再次储蓄不会重复加税。拨轮支持触屏拖动、惯性、鼠标滚轮、方向键及 PageUp / PageDown；调整余额时可切换增加 / 扣除。
- **最近使用**：金额编辑器中展示真实的任意金额储蓄历史，按金额、名称与类别去重。点金额载入修改，点旁边的 ＋ 直接再存一次；新流水有独立 ID，仍可撤销。手机上可切换「输入金额 / 最近使用」，桌面并排展示。想给快捷记录补充备注，可在足迹中编辑。
- **梦想清单**：添加商品价格、税率、最终含税运费、图片、类别和备注。可上传商品图，图片会压缩为本地数据。无图片时显示几何插画。
- **记录购买**：先显示扣款后的余额，再确认。允许明确确认后的负余额，以记录实际已发生的购买；一笔购买对应一条负数流水。删除该流水会撤回购买状态。
- **数据洞察**：按日、周、月、年查看储蓄；选择分类查看流水；按 7 / 30 / 90 天或全部查看余额趋势。图表使用真实数据，空白初始状态不会生成虚假记录。
- **储蓄足迹**：按本地日期、项目、类别筛选，编辑或删除记录。
- **数据与设置**：分类管理、税率、购买力门槛、备份恢复和可选云端配置。

这是对主动放弃消费的记录，不会执行真实银行转账。累计储蓄只统计储蓄流水；可用余额包含购买、支出与手动调整。多个目标共享同一笔资金，目标进度并不代表单独分配了资金。

## 数据保存与备份

每次操作立即保存到当前浏览器的 LocalStorage。刷新或重新打开同一个文件、同一个浏览器与同一网站来源时会恢复数据。文件移动、改名、不同浏览器、隐私浏览及清理网站数据可能影响本地存储；Safari 对 `file://` 存储的处理取决于浏览器版本与设置。应用会提示检测到的读写失败；请定期备份。

1. 在「数据与设置」选择 **导出备份**，下载 `savings-backup-YYYY-MM-DD.json`。
2. 恢复时选择 **恢复备份**，先查看记录数、金额和项目摘要。
3. **合并并恢复**：按 ID 去重，更新时间较新的版本生效；删除标记也会合并。重复导入不会重复累计。
4. **替换现有数据**：再次确认后完全替换本机数据。云端登录时需先退出，避免本机替换与云端记录自动混合。

备份带版本号、导出时间、全部实体、图片和删除标记；不含邮箱登录 token 或云端密钥配置。清空本机数据需要二次确认且不可撤销，请先备份。清空本机不会清空云端。

同一浏览器中的多个页面通过存储事件按记录合并；跨设备同步使用下面的独立云端模块。撤销保留最近 25 次操作，只在当前页面会话有效。

## GitHub Pages 发布

1. 在 GitHub 创建仓库，把 `index.html` 上传到仓库根目录。
2. 打开仓库 **Settings → Pages**。
3. 选择 **Deploy from a branch**，分支选 `main`，目录选 `/ (root)`，保存。
4. 等待 GitHub 显示站点地址，访问 `https://你的用户名.github.io/仓库名/`。

没有安装或编译步骤，不需要自行配置构建工作流。页面没有绝对资源路径，支持仓库子路径。`README.md` 和 SQL 不必上传也能运行本地功能。

网站首次访问需要网络。页面加载完成后断网，核心功能仍可用；本单文件版本不提供 Service Worker，因此不承诺断网时首次加载或重新打开 HTTPS 网站。下载后的 HTML 可直接离线打开。

## 可选 Supabase 同步

默认未配置、未登录，不会发出同步请求，也不会显示虚假的同步成功。你可以长期只用本地模式。

### 首次连接：照着应用里的 3 步做

打开 [SAVINGS.](https://weizikundavidwei.github.io/savings/#settings) 的「数据与设置」，找到「让积累，跟你走」。全部初始化代码和邮件模板已内置在这个页面，离线 HTML 也能直接复制，不必另外下载文件。

**01 · 准备云端空间**

1. 在 [Supabase 控制台](https://supabase.com/dashboard) 创建项目，等待准备完成。
2. 点击应用中的「复制初始化代码」。回到项目左侧 **SQL Editor → New query**，粘贴并点 **Run**。看到 **Success** 即可。代码与附带的 `supabase-setup.sql` 一致，可重复运行。
3. 打开 **Authentication → URL Configuration**，将 **Site URL** 与 **Redirect URLs** 都设置为 `https://weizikundavidwei.github.io/savings/`。
4. **Magic Link 邮件保持 Supabase 默认模板即可**，其中的 `{{ .ConfirmationURL }}` 会生成完整登录链接。如果之前改成了纯数字验证码模板，请恢复默认模板，或使用应用提供的可选兼容模板（同时提供链接与数字验证码）。

**02 · 粘贴连接信息**

在 Supabase 项目首页点 **Connect**，复制 **Project URL** 和 **Publishable key**，粘贴到应用的两个输入框，选择「保存并继续」。公开密钥以 `sb_publishable_` 开头，也可从 **Settings → API Keys** 获取；旧版 `anon` 公开密钥仍兼容。不要填数据库密码、`service_role` 或 `sb_secret_` 密钥。[官方密钥说明](https://supabase.com/docs/guides/getting-started/api-keys)

**03 · 用邮箱连接**

输入邮箱，点击「发送登录链接」，然后在**发起登录的同一浏览器和设备**打开最新邮件中的链接。返回网站后会自动恢复账户并触发既有同步；「上次成功同步」有真实时间才表示数据同步完成。

该流程使用官方 `supabase.auth.signInWithOtp()`，固定 `emailRedirectTo` 为 `https://weizikundavidwei.github.io/savings/`。应用使用 PKCE：发送时由 SDK 保存 verifier，返回后通过 `exchangeCodeForSession()` 换取会话；兼容旧版 implicit token 回调。地址中的认证参数会立即清除，会话通过官方 SDK 持久化与自动刷新；旧版本保存的登录也会迁移。退出仅清除此浏览器的认证缓存，保留储蓄账本。

数字 OTP 仍在「使用数字验证码（可选）」中。若邮件模板也包含 `{{ .Token }}`，可用 `verifyOtp()` 手动登录；默认模板只有链接时，直接点击链接即可，无需修改模板或配置 SMTP。

个人使用时，先用**创建 Supabase 项目的邮箱**。默认邮件服务只发送给项目团队成员邮箱，且发送次数有限；其他邮箱需配置自有 SMTP。[默认邮件服务说明](https://supabase.com/docs/guides/auth/auth-smtp)

### 第二台设备

在 Mac / iPhone 打开同一个网站，填入**相同项目地址与公开密钥**，用**同一邮箱**发送链接登录。每台设备都应自行发起登录，并在同一浏览器打开该设备收到的最新链接。第 01 步只做一次，第二台只需第 02、03 步。本机已有记录会与此账户合并。应用每分钟及重新联网、回到页面时检查同步。

### 常见问题

| 情况 | 怎么做 |
|---|---|
| 没有收到登录邮件 | 查看垃圾邮件；确认邮箱是项目团队邮箱；默认邮件服务限额较低，避免连续重发。其他邮箱需要自有 SMTP。 |
| 邮件只有一个登录链接 | 这是默认 Magic Link 邮件，直接点击即可，不必输入验证码。 |
| 提示找不到表或函数 | 确认在同一个 Supabase 项目运行了完整初始化代码，再尝试同步。 |
| 链接或验证码无效、过期 | 使用最新邮件；Magic Link 必须在发起登录的同一浏览器和设备打开。重新发送会更新本地 PKCE verifier。 |
| 点击邮件返回 localhost 或其他地址 | 在 Supabase 的 URL Configuration 中将 Site URL 与 Redirect URLs 配置为上面的完整 GitHub Pages 地址。 |
| 返回后提示缺少 verifier | 用发起登录的同一浏览器打开最新邮件链接，避免在内置邮件浏览器、其他浏览器或不同设备打开。 |
| 暂时离线 | 照常记账，联网后自动重试，本机数据保留。 |

邮箱链接与验证码配置参考 [Supabase 官方指南](https://supabase.com/docs/guides/auth/auth-email-passwordless)。Magic Link 不需要自定义 SMTP，但 Supabase 默认邮件服务仅向项目团队邮箱发送邮件，这项限制不会因切换认证方式而消失。应用提供复制失败时的手动选择和 SQL 下载；来回切换页面复制连接信息时，未提交的输入会暂存在当前页面中。

### 合并规则

- 流水、快捷项目、心愿、类别和偏好各有 ID、UTC 更新时间、修订 ID 和删除标记。
- 先拉取远端、逐条合并，再按每批最多 100 条推送，再次拉取确认。
- SQL 在冲突时原子比较 `(updated_at, rev)`，阻止旧版本覆盖新版本。
- 同一条记录并发修改时，时间较新的完整记录生效；时间相同则按修订 ID 稳定选取。不同记录分别保留。请保持设备系统时间准确。
- 删除保留 tombstone；旧设备不会使已删除记录重新出现。完整本地实体集合同时作为持久离线队列，不依赖内存中的待发列表。
- 会话会自动刷新。登录信息保存在当前浏览器，JSON 备份不携带登录信息；退出登录会保留本机记录。
- 「上次成功同步」只在真实的拉取、推送、再次拉取均成功后更新。云端错误不会回滚本地修改。

**账户注意**：本机数据属于当前浏览器，退出云端不会清空。若更换为另一邮箱登录，这些本机记录也会合并至新账户。若想建立完全独立的账户空间，请先导出、退出并清空本机，再登录新账户。

安全模型参考 [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security) 和 [Database Functions](https://supabase.com/docs/guides/database/functions)。本应用使用 `SECURITY INVOKER`，浏览器仅持有公开客户端密钥和当前用户会话。每个用户仅能读取、插入与更新自己的行。云端需要你自行配置才能进行真实的跨设备验证。
